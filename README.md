# Учебные архивы кафедр физики СПбГУ

Единый движок, пять представлений, четыре профильных архива. Статическая публикация GitHub Pages. Python 3.10+; дополнительных зависимостей нет. Сайт не является официальным ресурсом университета, если это отдельно не согласовано.

## Архитектура

- `site/` — единственный HTML-шаблон, JavaScript (поиск, навигация, загрузка), CSS, SVG и небольшие темы в `themes/`.
- `scripts/build.py` — собирает все страницы за один запуск. Не обращается к сети и не копирует общие файлы по кафедрам.
- `materials/3/…` … `materials/6/…` — прежние папки статистической физики. `Базовая часть` и `Общие дисциплины по выбору` каждого семестра являются единственным источником общих файлов всех четырёх кафедр. Остальные категории здесь относятся к статистической физике.
- `departments/quantum/materials/`, `departments/math/materials/`, `departments/field/materials/` — профильные материалы, практики и итоговая аттестация соответствующих кафедр.
- `.github/workflows/pages.yml` — одна сборка и публикация всех представлений.

| Раздел | Адрес относительно корня Pages |
| --- | --- |
| Статистическая физика | `/` |
| Квантовая механика | `/quantum/` |
| Математическая физика | `/math/` |
| Квантовая теория поля | `/field/` |
| Общий архив | `/common/` |

Прежние адреса страниц и файлов статистической физики сохраняются при публикации в прежнем репозитории. Общие файлы всех представлений имеют один фактический HTTP-адрес под `/materials/…`. Общий архив — отдельное представление той же папки, а не второе хранилище. Все пять представлений имеют взаимные ссылки. Общие дисциплины по выбору включены в общую базу; практики и аттестация остаются профильными. Названия и номера семестров взяты из предоставленных планов 25/5350/1 и 25/5511/1; см. `CURRICULUM.md` и `departments/*/CURRICULUM.md`. Внутри семестров профильные дисциплины обозначены как дисциплины по выбору. Факультативы и прочие профили не включены.

## Локальный запуск

```sh
python3 scripts/build.py
python3 -m http.server 8000 --directory _site
```

Откройте http://localhost:8000/ . В локальном режиме без указания репозитория веб-загрузка отключена; для изменения материалов редактируйте папки. Сборка создаёт `_site`, его нельзя добавлять в Git.

## Безопасная миграция действующего сайта статистической физики (macOS)

Сделайте резервную копию репозитория. Получите все актуальные изменения, рабочая копия должна быть чистой. Создайте ветку для миграции. Команды ниже предполагают, что распакованный `physics-engine` лежит рядом с локальной рабочей копией старого репозитория.

```sh
cd statphys-materials
git switch main
git pull --ff-only
git status --short
git switch -c multi-department
rsync -a ../physics-engine/site/ site/
rsync -a ../physics-engine/scripts/ scripts/
rsync -a ../physics-engine/.github/ .github/
rsync -a --ignore-existing ../physics-engine/materials/ materials/
rsync -a --ignore-existing ../physics-engine/departments/ departments/
cp ../physics-engine/README.md ../physics-engine/CURRICULUM.md .
printf '\n_site/\n__pycache__/\n.DS_Store\n' >> .gitignore
```

Команды не удаляют материалы и не перезаписывают существующие учебные файлы. Они заменяют известные файлы движка и workflow `pages.yml`. Если вы сами меняли код — проверьте diff. Проверьте, что других workflow, публикующих Pages, нет. Если есть — отключите их после проверки, чтобы они не перезаписывали новый сайт.

Если уже опубликован отдельный архив квантовой механики, скачайте его текущий репозиторий и импортируйте его материалы. Например, если он лежит рядом:

```sh
python3 scripts/import_quantum.py ../quantum-materials
python3 scripts/import_quantum.py ../quantum-materials --apply
```

Первая команда только показывает изменения; при несовпадающих файлах с одинаковым именем скрипт прекращает работу до копирования. Общие материалы попадут в `materials/`, профильные — в `departments/quantum/materials/`. Старый репозиторий не изменяется. Старые ссылки отдельного сайта квантовой механики автоматически не перенаправляются: оставьте старый сайт доступным до проверки миграции, после чего при необходимости добавьте перенаправление на новый адрес.

Проверьте сборку и содержимое изменений:

```sh
python3 scripts/build.py
python3 -m http.server 8000 --directory _site
```

После локальной проверки остановите сервер Ctrl+C, затем:

```sh
git add -A
git diff --cached --stat
git commit -m "Unify physics archives"
git push -u origin multi-department
```

Откройте pull request из `multi-department` в `main` в GitHub и проверьте изменения перед Merge. В Settings → Pages → Source должно стоять GitHub Actions. После merge сборка запускается автоматически. Весь комплект обновляется одним коммитом. Переменная `STATPHYS_URL` больше не нужна. При публикации с нуля вместо миграции можно создать новый пустой публичный репозиторий, поместить туда содержимое этого проекта и включить Pages (GitHub Actions).

## Загрузка учебных материалов

В каждой раскрытой дисциплине кнопка «Загрузить файлы» позволяет редактору выбрать папку и несколько файлов. Для общих дисциплин с кафедральных сайтов есть ссылка на общий архив; загружайте туда. Загрузка осуществляется непосредственно через GitHub API с токеном пользователя, который имеет права записи в данный репозиторий, либо через штатный интерфейс GitHub. Не храните токены в проекте и не передавайте свой токен другим пользователям. Лимит загрузчика 25 МиБ на файл, генератор отклоняет файлы более 100 МиБ. Общие и профильные файлы публикуются открыто, не размещайте материалы, которые нельзя распространять.

Приглашённый редактор репозитория имеет доступ к его содержимому, не только к папкам своей кафедры. Эта версия не реализует анонимную загрузку, разграничение прав по кафедрам или модерацию заявок; для этого нужна другая схема доступа (например, pull requests с проверкой или отдельный сервер авторизации).

## Как добавить ещё кафедру

Создайте `departments/<id>/materials/3…6/`, зарегистрируйте представление в `SITES` и цикле профильных каталогов в `scripts/build.py`, добавьте `site/themes/<id>.css` и `site/art/<id>.svg`. Общий движок остаётся тем же. При публикации в одном репозитории отдельный GitHub Fork и синхронизация по расписанию не нужны.
